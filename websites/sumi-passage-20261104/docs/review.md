## 帖子实际展示了什么

主帖声称作者在 24 小时内利用 AI 完成原创可玩游戏；这个工时与模型能力是作者的陈述，未独立验证。演示呈现第三人称山崖探索：斗笠旅人、竖直石壁、鸟居、松树、云海、平台跳跃、攀爬、索道与悬桥。视觉统一比 UI 复杂度更关键，环境大部分保持低饱和墨绿灰色，朱红建筑与浅色斗笠承担识别作用。

作者列出的流程：

1. [确立视觉参考](https://x.com/xikhar/status/2117776297913106657)：以 Flux 3 Max / fal 生成参考视频，统一世界、人物与画面气质。
2. [重建场景](https://x.com/xikhar/status/2117776300236820925)：从视频取帧，在 Blender 重建资产，放入 Three.js；作者描述使用并行构建与检查工作流。
3. [创建角色](https://x.com/xikhar/status/2117776303378288897)：GPT Image 补齐四侧视图，Tripo 转为模型，再增加布料与动作。
4. [先验证玩法](https://x.com/xikhar/status/2117776305815249262)：先实际游玩原型，确认可操作，再扩建。
5. [扩展关卡概念](https://x.com/xikhar/status/2117776308256362997)：按已有画风为每个关卡生成多张概念图。
6. [场景构建与反复迭代](https://x.com/xikhar/status/2117776311368511672)：让概念图变为可游玩关卡，持续报告并修复问题。

## 技术判断

这是一条「视觉参考 → 资产生产 → 实时游戏」管线。AI 图像、Tripo 与 Blender 属于制作阶段工具，不需要在访客浏览器中运行。Three.js 负责场景渲染与动画；能否正常游玩取决于另外实现的移动、重力、碰撞、摄像机与状态管理。单纯放一张背景图或播放参考视频，不能重现这类交互。

值得借鉴：用少数标志性元素维持风格、先做一个可玩的完整循环、把角色与平台轮廓做清楚、用雾分隔景深。需要补强：关卡可达性检查、控制提示、暂停、落崖恢复、存档以及移动端输入。

## 本次原创作品：《山有归途》

网页以 Three.js + TypeScript + Vite 构建，直接依赖均固定版本。沿用山崖、云雾、斗笠与朱门的视觉方向；场景、角色、材质纹理、图标与 UI 均在本项目内重新制作。

实际实现：

- 七座可落脚山崖、双鸟居、曲松、石灯、远山与云雾。
- 可控旅人、斗笠与佩剑、基于顶点形变的披风和衣带摆动、行走与腾空姿态。
- 固定 120Hz 模拟、重力、落地检测、跳跃输入缓冲与离崖容错、快跑。
- 三枚山印、途中存档、坠落恢复、终点条件、完成统计。
- 可旋转缩放的跟随镜头、键盘与触屏控制、暂停手记、原创合成风声与提示音。
- 本地存档校验、无 WebGL 时的明确提示、降低动态效果设置。

**没有声称调用 Opus / Flux / GPT Image / Tripo / Blender。** 本次角色和环境使用原创程序几何；布料是视觉顶点动画，并非真实布料物理。没有复用视频、截图或原作者的游戏模型作为运行素材。攀爬、索道、战斗与八关完整世界不在本次短途游戏范围内。

## 视觉系统说明

已使用 `ui-ux-pro-max`：首次 gaming 查询偏电竞风，重试 heritage / Japanese 查询确认了 Noto Serif 系列与克制留白方向，但产品模板仍偏通用网站，因此未保存其模板或直接照搬。采用的项目设计为原创山水方向：宣纸白、松墨绿、朱砂红；系统宋体优先，无远程字体请求；全屏场景配轻量界面，清晰焦点、44px 工具按钮、手机触控、降低动态效果。

## 后续接入 AI / Blender 资产

需要时可将已获得使用许可的模型放入本项目 `public/models/`，用 Three.js GLTFLoader 替换 `World.makeCharacter()` 或场景对象；控制器仍使用独立的简单碰撞数据。导出前统一米制尺寸、原点、朝向、动画片段、材质与贴图。不要直接把高面数模型当碰撞体。当前网页不依赖任何外部服务、密钥或其他视频目录。
